1. Мета роботи та вхідні артефакти

Мета: Опанувати практичну трансформацію затвердженої специфікації вимог (SRS Baseline v1.0) на керований календарний план реалізації у парадигмі Specification-Driven Development (SDD). Набути навичок декомпозиції вимог на SDD-тікети, моделювання життєвого циклу задачі в системі багтрекінгу, оптимізації взаємодії людини та ШІ-агента, розрахунку критичного шляху (CPM) з урахуванням людських обмежень пропускної здатності, а також сформувати реєстр класичних та ШІ-специфічних ризиків проєкту.

Вхідні артефакти: затверджена базова специфікація spec/srs.md (Baseline v1.0), глосарій spec/glossary.md, набір BDD-сценаріїв spec/bdd-scenarios.md, початкова матриця простежуваності spec/traceability-matrix.md та протокол контрольної точки logs/spec-gate.md.

2. Налаштування системи багтрекінгу та життєвий цикл задачі

Для трекінгу задач обрано платформу GitHub Issues & GitHub Projects. Життєвий цикл задачі регламентовано послідовністю станів:

  • New / Draft — виділення атомарної одиниці робіт на основі стабільного ID вимоги з SRS.
  • Backlog / Planned — оцінка трудовитрат, встановлення зв'язків та визначення черги виконання.
  • In Progress (Dev / TDD) — активна розробка. Дотримується правило блокування: реалізація коду фічі починається лише після наявності відповідного тесту.
  • Verification (CI / Testing) — автоматизований прогін pytest, лінтинг PEP 8, бенчмарк SLA (Latency < 50 мс).
  • Validation (Review / Gate) — людський когнітивний аудит ергономіки, відповідності задуму та ухвалення рішення Gate.
  • Done / Closed — успішне завершення задачі, злиття коду в гілку main, оновлення матриці RTM.
  • Blocked / Revise — зупинка робіт у разі виявлення прогалин у SRS (ініціює створення Адендуму).
  • Rejected — відхилення неспецифікованих пропозицій кодингового агента (захист від Gold Plating).

5. Календарний розрахунок критичного шляху (CPM) та Human Bottleneck

Математичні результати CPM:
  • Загальна календарна тривалість (Critical Path): 10.50 годин.
  • Сумарні трудовитрати проєкту: 11.60 людино-годин.
  • Частка ШІ-агента: 4.60 год (39.7%).
  • Частка людини-інженера: 7.00 год (60.3%).

Людські дії як критичне «вузьке місце» (Human-in-the-loop bottleneck): Незважаючи на здатність мовної моделі генерувати код за лічені хвилини, понад 60% часу на критичному шляху займає діяльність людини: рецензування вимог, рев'ю сценаріїв безпеки та ухвалення управлінських рішень на контрольних точках Gate. Це доводить, що реальна пропускна здатність інженерного конвеєра лімітується саме когнітивною швидкістю людини, а не швидкістю кодогенерації.

8. Контрольна точка PLAN-GATE та висновки

Перед початком систематичної реалізації проведено аудит за контрольним чек-листом у logs/plan-gate.md. Ухвалено рішення STATUS: APPROVED (GO), що розблоковує виконання першого спринту розробки.

Підсумковий висновок: Мета лабораторної роботи досягнута повністю. Сформовано наскрізний керований план SDD-проєкту, усунуто специфічні ризики автоматизованої кодогенерації, доведено критичну роль людини як головного лімітуючого фактора швидкості інженерного циклу та забезпечено 100% простежуваність артефактів.
