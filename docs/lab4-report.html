1. Мета роботи та вхідні артефакти

Мета роботи: Опанувати API-first підхід у парадигмі Specification-Driven Development (SDD) та здійснити перехід від затверджених вимог (SRS Baseline v1.0) до формального машинозчитуваного контракту REST API. Спроєктувати ресурси, URI, схеми запитів та відповідей (DTO), єдину модель помилок RFC 7807 (Problem Details), створити специфікацію OpenAPI 3.0.3, провести її автоматичну валідацію лінтером, розгорнути Mock API без коду сервера, верифікувати 14 позитивних і негативних сценаріїв та провести контрольну точку API-GATE.

Вхідні артефакти: Затверджена специфікація SRS v1.0 (spec/srs.md), глосарій термінів (spec/glossary.md), BDD-сценарії (spec/bdd-scenarios.md), SDD-беклог та матриця RTM, сформовані в ЛР2 і ЛР3.

2. Модель REST-ресурсів та декомпозиція

Згідно з принципами REST та єдиною мовою глосарію (Ubiquitous Language), систему декомпозовано на 4 ключові ресурси:

  • /references — основні картки референсів (створення, кон'юнктивна фільтрація за тегами, повнотекстовий пошук, пагінація).
  • /collections — тематичні користувацькі колекції та дошки проєктів (N:M зв'язок).
  • /categories — класифікація верхнього рівня з механізмом нульової втрати даних (Fallback to General).
  • /health — системний ендпоінт перевірки працездатності сервісу та бенчмарку SLA (< 50 мс).
Принцип інкапсуляції (Information Hiding)
Внутрішній агрегат-менеджер Catalog та структура сховища надійно приховані від клієнта. Публічний інтерфейс оперує виключно уніфікованими DTO, унеможливлюючи витік деталей реалізації бекенду.

4. Єдина модель помилок (RFC 7807 Problem Details)

Усі помилкові HTTP-відповіді стандартизовано за стандартом application/problem+json:

{
  "type": "https://api.design-refs.local/errors/validation-error",
  "title": "Validation Failed",
  "status": 400,
  "code": "VALIDATION_FAILED",
  "detail": "Required fields validation failed.",
  "instance": "/api/v1/references",
  "timestamp": "2026-10-31T14:05:00Z",
  "invalid_params": [
    {
      "name": "title",
      "reason": "Title is required and cannot be empty."
    }
  ]
}

Застосовано коди: UNSAFE_URL_PROTOCOL (422), VALIDATION_FAILED (400), RESOURCE_NOT_FOUND (404), PROTECTED_RESOURCE (400), MALFORMED_JSON (400) та INTERNAL_ERROR (500).
