# Регламент контролю версій та SDD-конвенція комітів

## 1. Префікси повідомлень комітів (SDD Convention)
Для забезпечення однозначної простежуваності зв'язку між артефактами життєвого циклу розробки встановлено таку конвенцію:
- `spec:` — створення або зміна специфікацій, вимог, концептуальних документів (каталог `/spec`).
- `feat:` — зміни у вихідному коді та модулях інформаційної системи (каталог `/src`).
- `test:` — додавання або зміна модульних, інтеграційних чи димових тестів (каталог `/tests`).
- `docs:` — оновлення інструкцій, технічної документації та регламентів (каталог `/docs`).
- `gate:` — фіксація рішень контрольних точок (якість коду, верифікація злиття гілок, вирішення конфліктів у `/logs`).

## 2. Модель гілкування (Branching Model)
- `main` — стабільна гілка з валідованими SDD-артефактами.
- `agent/<feature-name>` — ізольована гілка для генерації та експериментів штучного інтелекту.
- `human/<feature-name>` — ізольована гілка для ручних змін інженера.

Будь-яке злиття функціональних гілок у `main` проходить обов'язковий контроль відповідності затвердженому артефакту специфікації (процедура GIT-GATE).
