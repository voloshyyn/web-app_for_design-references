# Поведінкові BDD-сценарії (Specification by Example)

- **Проєкт:** Система каталогізації та швидкого пошуку дизайн-референсів
- **Формат опису:** Gherkin (Given — When — Then)
- **Призначення:** Специфікація перевірюваної поведінки системи для автоматизованого Acceptance/Unit-тестування (ATDD/BDD).

---

## Фіча 1: Управління та валідація референсів (Reference Management)

### Сценарій SCN-01: Успішне додавання нового валідного референсу (Happy Path)
- **Пов'язана вимога:** `REQ-F-001`, `REQ-F-002`, `REQ-F-004`
- **Критерій прийняття:** `AC-F-001.1`, `AC-F-002.1`, `AC-F-004.1`

```gherkin
Feature: Створення нового референсу

  Scenario: Користувач зберігає валідний референс із тегами та категорією
    Given користувач відкрив форму додавання референсу
    And у системі зареєстрована категорія "UI/UX"
    When користувач вводить назву "Dark Minimalist Dashboard"
    And користувач вказує URL джерела "https://dribbble.com/shots/example-dash"
    And користувач обирає категорію "UI/UX"
    And користувач додає теги "dashboard, minimalism, style:dark"
    And користувач додає персональну нотатку "Звернути увагу на відступи карток та контраст шрифтів"
    And користувач натискає кнопку "Зберегти"
    Then система успішно зберігає референс у каталозі
    And присвоює йому унікальний ідентифікатор
    And референс містить рівно 3 нормалізовані теги: ["dashboard", "minimalism", "style:dark"]
    And референс асоційований із категорією "UI/UX"
    And запис з'являється у списку збережених матеріалів без оновлення всієї сторінки
```

### Сценарій SCN-02: Відхилення збереження референсу при невалідному або небезпечному URL (Validation & Security)
- **Пов'язана вимога:** `REQ-F-001`, `REQ-NF-004`
- **Критерій прийняття:** `AC-F-001.2`, `AC-NF-004.1`

```gherkin
Feature: Валідація вхідних даних референсу

  Scenario Outline: Спроба створення референсу з недопустимою адресою URL
    Given користувач заповнює форму створення референсу
    When користувач вказує назву "Небезпечне посилання"
    And користувач вводить адресу джерела "<invalid_url>"
    And користувач підтверджує створення
    Then система блокує операцію збереження
    And повертає помилку валідації "Недопустимий формат URL. Дозволено тільки http:// або https://"
    And стан каталогу залишається незмінним

    Examples:
      | invalid_url                         |
      | javascript:alert('XSS')            |
      | data:text/html,<script>bad()</script>|
      | ftp://files.example.com/mockup.png |
      | not-a-valid-url-string             |
      |                                    |
```

## Фіча 2: Фільтрація та фасетний пошук (Filtering & Faceted Search)

### Сценарій SCN-03: Кон'юнктивна фільтрація за декількома тегами (AND-семантика)
- **Пов'язана вимога:** `REQ-F-004`, `REQ-F-005`
- **Критерій прийняття:** `AC-F-005.1`

```gherkin
Feature: Фільтрація каталогу за тегами

  Scenario: Пошук референсів за комбінацією двох тегів
    Given у каталозі збережено такі референси:
      | title               | category | tags                         |
      | "Mobile FinTech"    | "UI/UX"  | "mobile, fintech, dark"      |
      | "Web Crypto Portal" | "UI/UX"  | "web, fintech, light"        |
      | "Mobile Game UI"    | "UI/UX"  | "mobile, gamedev, dark"      |
      | "Branding Identity" | "Branding"| "minimalism, print"         |
    When користувач обирає фільтр за тегами "mobile" ТА "dark"
    Then система повертає рівно 2 референси:
      | title               |
      | "Mobile FinTech"    |
      | "Mobile Game UI"    |
    And референси "Web Crypto Portal" та "Branding Identity" виключаються з результатів вибірки
    And час розрахунку фільтрації становить менше 50 мілісекунд
```

### Сценарій SCN-04: Параметризований пошук за фасетним префіксом
- **Пов'язана вимога:** `REQ-F-004`, `REQ-F-005`
- **Критерій прийняття:** `AC-F-004.2`, `AC-F-005.2`

```gherkin
Feature: Фасетна фільтрація за префіксом namespace:value

  Scenario: Користувач здійснює вибірку за стильовим фасетом
    Given у системі є референси з фасетними тегами "style:brutalism", "style:minimalism", "style:skeuomorphism"
    When користувач застосовує запит фільтра "style:brutalism"
    Then у результатах відображаються лише референси, які містять точний фасет "style:brutalism"
    And звичайні теги без префіксу "style:" не призводять до помилкового збігу
```

## Фіча 3: Цілісність даних та збереження зв'язків (Data Integrity)

### Сценарій SCN-05: Безпечне видалення категорії з каскадним перепризначенням (Fallback)
- **Пов'язана вимога:** `REQ-F-002`, `REQ-F-008`, `REQ-NF-003`
- **Критерій прийняття:** `AC-NF-003.1`

```gherkin
Feature: Захист цілісності при видаленні класифікаторів

  Scenario: Видалення користувацької категорії не призводить до втрати референсів
    Given існує категорія "3D Modeling"
    And існує референс "Sci-Fi Helmet Render", прив'язаний до категорії "3D Modeling"
    When користувач видаляє категорію "3D Modeling"
    Then система успішно видаляє категорію "3D Modeling" зі списку доступних
    And референс "Sci-Fi Helmet Render" залишається в каталозі
    And категорія референсу "Sci-Fi Helmet Render" автоматично змінюється на системну "General"
    And жодні теги або нотатки референсу не втрачаються
```

## Фіча 4: Повнотекстовий пошук (Full-Text Search)

### Сценарій SCN-06: Пошук за ключовими словами в нотатках та заголовках
- **Пов'язана вимога:** `REQ-F-006`
- **Критерій прийняття:** `AC-F-006.1`

```gherkin
Feature: Повнотекстовий контекстний пошук

  Scenario: Знаходження референсу за інсайтом, залишеним у персональній нотатці
    Given існує референс із заголовком "SaaS Pricing Page"
    And поле нотаток містить текст "Цікава неоморфна тінь на перемикачі місячного тарифу"
    When користувач вводить у рядок пошуку "неоморфна тінь"
    Then референс "SaaS Pricing Page" відображається у списку знайдених результатів
    And пошук працює без урахування регістру введених літер
```
